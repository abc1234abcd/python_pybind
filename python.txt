5. due to GIL(global interpreter lock), only one thread executes python bytecode at a time. good for i/o bound task(network, file reading/writing, websockets) - threads can wait on i/0 while others run.

for cpu bounded task, regardless how much more threads are open, only one thread runs python bytecode at a time, therefore, the result has little to no speed up from multi-threading for
CPU bounded task -> solution: multi-processing, then each process has its own python iterpreter and gil.

for i/o bounded task, the most of time waiting for external resources(network, API, database etc) are not blocked by GIL when waiting(). therefore, threads can switch while one thread is 
waiting for i/o.

gil is a mutex(互斥锁): gil is a mutex that protects python object. why python objects need to be protected? : in concurrent programming, to prevent multiple threads or processes from 
accessing/modifying it at the same time in unsafe ways as in race conditions
